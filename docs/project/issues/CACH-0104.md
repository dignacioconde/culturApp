# CACH-0104 — QA financiera y cierre de Beta 25

## Objetivo

Bloquear el cierre de Beta 25 hasta confirmar que liquidacion neta minima no rompe formulas, RLS, portabilidad, dashboard ni detalles financieros.

## Alcance

- Ejecutar checks locales de app y Product Brain.
- Verificar proyecto con ingreso directo, evento hijo, gasto interno y gasto repercutible.
- Verificar evento independiente con gasto repercutible.
- Confirmar que `cobro bruto/hora` conserva su regla estrecha.
- Documentar estado remoto de migracion Supabase: aplicado/verificado o pendiente/bloquea funcionalidad.
- Preparar release notes y estado final antes de PR a `main`.

## Criterios de aceptacion

- [x] AC1: `npm run lint`, `npm run test`, `npm run build` y `npm run pb:guard` pasan.
- [x] AC2: `npm run verify:pr -- --base origin/main` pasa o el bloqueo queda documentado.
- [x] AC3: Smoke financiero cubre proyecto/evento con gastos internos y repercutibles.
- [x] AC4: Dashboard mensual conserva sus KPIs principales de ingresos/cobros y trabajos.
- [x] AC5: Migracion remota queda verificada o marcada como pendiente/bloqueante.
- [x] AC6: Memoria durable se actualiza si aparece aprendizaje reutilizable; si no, se declara no aplica.

## Plan tecnico

Usar memoria financiera como contrato. Si una prueba falla por formula, corregir el slice que introdujo la regresion antes de cerrar. Si la migracion remota no puede aplicarse/verificarse, la release no debe marcarse como production-ready.

## Escenarios SDD

- Cuando todos los slices estan integrados, entonces los checks locales y Product Brain pasan sin artefactos generados pendientes.
- Cuando la migracion no esta aplicada en remoto, entonces la release documenta el bloqueo funcional y no se marca como released.
- Cuando hay smoke de detalles financieros, entonces incluye al menos un proyecto con eventos hijos y un evento independiente.

Contratos afectados:

- `npm run lint`

Riesgo principal: cerrar la release con schema local no aplicado o con dashboard alterado. Rollback: mantener issue/release abierta y documentar bloqueo; no marcar `release_phase: released`.
