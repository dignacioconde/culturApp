# CACH-0098 - Metricas locales para retrieval y SDD

## Objetivo

Anadir un sistema local y determinista de metricas para comprobar si `pb:retrieve`, `pb:ready-check` y `pb:sdd-check` siguen orientando bien a los agentes y detectando specs debiles.

## Alcance

Incluido:

- Crear `pb:metrics` como CLI local advisory con salida humana y JSON.
- Medir calidad y latencia de casos golden de retrieval.
- Medir fixtures temporales de SDD/ready-check usando `PRODUCT_BRAIN_REPO_PATH`.
- Versionar fixtures y baseline en `scripts/brain/fixtures/`.
- Documentar que las metricas no se integran aun en `pb:guard` ni CI como bloqueo.

Fuera de alcance:

- Embeddings, vector DB, agentes reales, PR mining, APIs externas o servicios remotos.
- Integrar `pb:metrics` en `pb:guard`, `verify:pr` o CI.
- Guardar historico operativo de ejecuciones en `.memory/` o `docs/project/`.

## Criterios de aceptacion

- [x] AC1: Existe `npm run pb:metrics` y muestra metricas legibles de retrieval y SDD/ready.
- [x] AC2: `npm run pb:metrics -- --json` devuelve una estructura parseable sin timestamps.
- [x] AC3: `npm run pb:metrics -- --update-baseline` actualiza la baseline versionada deliberadamente.
- [x] AC4: Los fixtures SDD se ejecutan en un directorio temporal mediante `PRODUCT_BRAIN_REPO_PATH` y no escriben en `docs/project/`.
- [x] AC5: Las regresiones de latencia/calidad se reportan como warnings advisory; solo fallan fixtures criticos rotos.

## Plan tecnico

Anadir `scripts/brain/metrics.mjs` reutilizando los CLIs existentes por `spawnSync` para medir el comportamiento real de los comandos. Guardar casos golden y baseline en `scripts/brain/fixtures/`. Crear issues SDD efimeras en `os.tmpdir()` y ejecutar `ready-check`/`sdd-check` con `PRODUCT_BRAIN_REPO_PATH` apuntando al fixture temporal.

## Escenarios SDD

- Cuando se ejecute `pb:metrics`, entonces se calculan metricas de retrieval y SDD sin usar servicios externos ni escribir en Product Brain.
- Cuando un caso golden pierda resultados esperados o suba de latencia, entonces el informe lo marca como warning advisory.
- Cuando un fixture SDD critico falle contra su resultado esperado, entonces `pb:metrics` devuelve error.

## Contrato tecnico

- `scripts/brain/metrics.mjs` define la CLI y orquesta `pb:retrieve`, `pb:ready-check` y `pb:sdd-check`.
- `scripts/brain/fixtures/metrics-retrieval-cases.json` define queries/issues y resultados esperados.
- `scripts/brain/fixtures/metrics-baseline.json` guarda la baseline versionada.
- `package.json` expone `pb:metrics`.

## Riesgos y rollback

Riesgo principal: introducir ruido por latencias variables. Mitigacion: latencia advisory y fixtures funcionales como unico bloqueo fuerte.

Rollback: revertir esta slice de tooling y fixtures. No toca runtime, datos, Supabase ni produccion.
