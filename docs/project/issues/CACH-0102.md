# CACH-0102 — Integrar hooks y helpers de liquidacion neta

## Objetivo

Exponer en la capa de datos y helpers financieros la liquidacion neta minima definida para Beta 25, sin que los componentes llamen a Supabase directamente.

## Alcance

- Actualizar `useExpenses` para leer/escribir los campos nuevos con `user_id` siempre derivado del usuario autenticado.
- Crear o ampliar helpers puros para calcular resumen de liquidacion por evento y por proyecto.
- Mantener los modos de filtro de `useIncomes` y `useExpenses`: usuario completo, evento, proyecto directo y proyecto + eventos hijos.
- Actualizar export/import CSV para no perder los campos nuevos.
- Añadir tests unitarios de helpers y portabilidad.

Queda fuera: UI final, schema remoto, cambios del dashboard mensual y cualquier calculo fiscal legal.

## Criterios de aceptacion

- [x] AC1: Los hooks preservan carga, error, CRUD y `refetch` sin llamadas Supabase desde componentes.
- [x] AC2: Los helpers calculan bruto, retencion, gastos internos, gastos repercutibles y neto operativo para evento y proyecto.
- [x] AC3: Los ingresos directos de proyecto no entran en `cobro bruto/hora`.
- [x] AC4: Export/import conserva los campos nuevos sin aceptar `user_id` importado.
- [x] AC5: Los tests cubren proyecto con evento hijo, evento independiente, gasto interno y gasto repercutible enlazado.

## Plan tecnico

Usar los contratos de `src/lib/dashboardFinance.js`, `src/lib/financeForms.ts`, `src/hooks/useIncomes.js`, `src/hooks/useExpenses.js` y portabilidad. Si aparece duplicacion de calculo entre ProjectDetail y EventDetail, extraer helper puro antes de tocar UI.

## Escenarios SDD

- Cuando un proyecto tiene ingresos/gastos directos y eventos hijos, entonces el helper de proyecto agrega ambos niveles sin duplicar eventos.
- Cuando un evento tiene un gasto repercutible enlazado a un ingreso, entonces el helper lo separa de los gastos internos.
- Cuando se exportan datos, entonces los campos nuevos viajan sin `user_id`; al importar, se recrean con el usuario autenticado.

## Contrato tecnico

Contratos afectados:

- `src/hooks/useExpenses.js`
- `src/hooks/useIncomes.js` solo si el contrato de enlace lo exige.
- `src/lib/**` helpers financieros y tests.
- `src/lib/portability/**`
- `src/hooks/useDataPortability.js`

## Riesgos y rollback

Riesgo principal: alterar formulas financieras existentes por reutilizar un helper nuevo de forma demasiado amplia. Rollback: aislar el helper de liquidacion neta y no sustituir KPIs actuales hasta que los tests prueben equivalencia.

## Validacion

- App -> `npm run lint` y `npm run build`.
- Product Brain -> `npm run pb:ready-check -- CACH-0102` antes de mover a `ready`.

## Resultado

Implementados helpers y capa de datos:

- `src/lib/netSettlement.ts`: calcula bruto, cobrado, por cobrar, IRPF sobre cobrado, gastos internos, gastos repercutibles, gastos enlazados y neto operativo.
- `getGrossHourlyRateSummary`: mantiene la regla estrecha de `cobro bruto/hora`, solo con ingresos cobrados que tienen `event_id`.
- `src/hooks/useExpenses.js`: conserva contrato de carga/error/CRUD/refetch, deriva `user_id` del usuario autenticado y descarta cualquier `user_id` recibido en payload.
- Portabilidad JSON/CSV conserva `expense_kind` y `reimbursed_by_income_id` en exportacion.
- Import CSV usa `income_key` y `reimbursed_by_income_key`; no acepta `user_id` ni `reimbursed_by_income_id` crudos.
